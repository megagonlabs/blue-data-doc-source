Case 3 — Content changes  →  new chunk IDs  →  stale v1 chunks
--------------------------------------------------------------------

  v1 document_id : doc_f2bbe8ee8a299104
  v1 chunk IDs   : ['doc_f2bbe8ee8a299104_chunk_000000']
  Store size     : 1

  v2 document_id : doc_2d04e9ca64e2be68
  v2 chunk IDs   : ['doc_2d04e9ca64e2be68_chunk_000000']
  Store size     : 1

  Overlapping IDs (same chunk in v1 and v2) : 0
  Stale v1-only IDs still in store          : 1

  ✓ In-process pipeline detects content change and removes stale
    chunks automatically (same path, new hash → old chunks deleted).

  ⚠  Cross-process: a NEW pipeline has no memory of v1.
     Use DOCUMENT.DELETE before re-ingesting in a fresh process:

       source.execute_query({
           "op": "DOCUMENT.DELETE",
           "document_id": "doc_f2bbe8ee8a299104",
           "chunk_count": 1,
       })
