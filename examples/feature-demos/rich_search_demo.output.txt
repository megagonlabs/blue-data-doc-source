------------------------------------------------------------------------
  Step 5 — context_chunks parameter — neighbor context on/off
------------------------------------------------------------------------

  context_chunks=1  (default) — includes text from chunks
  immediately before and after each result in the document.

  context_chunks=1  →  results with 'before': 3, results with 'after': 3
  context_chunks=0  →  results with no 'context' key: 3

  Sample with context (context_chunks=1):
    rank=1  text: '5.1 Filing a Claim In-network providers submit claims direct'…
           before: 'family. Once this limit is reached, the plan cover'…
           after:  'out-of-network reimbursements. 5.3 Disputes and Ap'…
    rank=2  text: '3.1 General Exclusions This policy does not cover: cosmetic '…
           before: '$70 copay per 30-day supply - Tier 4 (Specialty): '…
           after:  'any condition for which the policyholder received '…
    rank=3  text: 'The Provider agrees to deliver software development services'…
           before: 'This Service Agreement ("Agreement") is entered in'…
           after:  'Client shall pay Provider a monthly retainer of $1'…

  Caveat: neighbor lookup uses an in-process chunk index populated
  at ingest time. Chunks ingested in a previous process run are not
  available as neighbors — 'context' keys are silently omitted for
  those results. Re-ingest in the same process to restore context.

========================================================================
  Summary — DOCUMENT.SEARCH vs DOCUMENT.SEARCH_RICH
========================================================================

  Feature              DOCUMENT.SEARCH        DOCUMENT.SEARCH_RICH
  --------------------------------------------------------------------
  Return type          list[dict]             dict
  Ranked chunks        ✓ raw chunk fields     ✓ same KNN query
  Citation block       ✗ fields scattered     ✓ {doc_id, file, page, section}
  Neighbor context     ✗ not available        ✓ context.before / after
  Grouped by document  ✗ flat list only       ✓ by_document + top_sections
  Result count / doc   ✗ must count manually  ✓ match_count per document

  When to use rich search:
    - Feeding results to an LLM for answer generation (RAG)
    - Building citation-aware UI (show 'page 3, §Coverage' links)
    - Multi-document corpuses where grouping by source matters

  When plain search is enough:
    - Simple ranked snippet retrieval
    - When you process results yourself downstream
    - Testing / debugging — fewer nested fields to inspect
