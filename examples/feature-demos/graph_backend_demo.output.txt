Step 4 -- Section nodes — Document -[:HAS_SECTION]-> Section -[:HAS_CHUNK]-> Chunk
------------------------------------------------------------------------

  Each distinct section_title per document becomes a Section node.
  Section nodes sit between the Document and its Chunks in the graph,
  preserving document structure for structural navigation.

Step 6 -- Sequential navigation — Chunk -[:NEXT]-> Chunk / Chunk -[:PREV]-> Chunk
------------------------------------------------------------------------

  Every consecutive pair of chunks in a document is linked with NEXT and PREV.
  Walk the chain to expand context around a hit — without storing full text in
  each node (text_preview is capped at 200 chars for node weight).

  NEXT edges in corpus: 0

  Walking NEXT chain from first chunk of 'employment_chen.txt':
    [0] chunk:doc_ab47570d1bcac412_chunk_000000  'This Employment Agreement is entered into between Acme '

  Use DOCUMENT.GRAPH_QUERY to walk this chain programmatically:
    source.execute_query({
        'op': 'DOCUMENT.GRAPH_QUERY',
        'node_id': 'chunk:doc_abc_chunk_000003',
        'edge_type': 'NEXT',
        'direction': 'out',
    })

------------------------------------------------------------------------
Step 7 -- Entity -[:APPEARS_IN]-> Document — direct document membership
------------------------------------------------------------------------

  Every entity gets a direct APPEARS_IN edge to each Document it appears in.
  This lets you answer 'which documents mention Acme Corp?' in one hop,
  rather than a two-hop traversal (entity → chunk → document).

  APPEARS_IN edges in corpus: 21

  Documents that 'Acme Corp' APPEARS_IN (3 document(s)):
    → [Document]  doc:doc_ab47570d1bcac412  (employment_chen.txt)
    → [Document]  doc:doc_3119d4c48e607d0e  (vendor_apex.txt)
    → [Document]  doc:doc_ce3602ae6b6dec3a  (incident_0088.txt)

  Compare: the old two-hop path (entity → MENTIONS ← chunk → HAS_CHUNK ← doc)
  is still valid but APPEARS_IN makes document membership a single hop.

Step 9 -- DOCUMENT.GRAPH_QUERY — general graph traversal via op interface
------------------------------------------------------------------------

  DOCUMENT.GRAPH_QUERY is a general-purpose traversal op. Start from any
  node ID, follow any edge type, in any direction, with an optional limit.

  Examples:

    # All chunks in a document
    source.execute_query({
        'op': 'DOCUMENT.GRAPH_QUERY',
        'node_id': 'doc:doc_abc123',
        'edge_type': 'HAS_CHUNK',
        'direction': 'out',
    })

    # Documents that mention a given entity (APPEARS_IN)
    source.execute_query({
        'op': 'DOCUMENT.GRAPH_QUERY',
        'node_id': 'entity:PROPER_NOUN:acme corp',
        'edge_type': 'APPEARS_IN',
        'direction': 'out',
    })

    # Next chunk in reading order
    source.execute_query({
        'op': 'DOCUMENT.GRAPH_QUERY',
        'node_id': 'chunk:doc_abc123_chunk_000003',
        'edge_type': 'NEXT',
        'direction': 'out',
        'k': 1,
    })

    # All sections in a document
    source.execute_query({
        'op': 'DOCUMENT.GRAPH_QUERY',
        'node_id': 'doc:doc_abc123',
        'edge_type': 'HAS_SECTION',
        'direction': 'out',
    })

========================================================================
Summary
========================================================================

  Full graph schema written during ingest:

    (Document {document_id, file_name, document_type,
               mime_type, ingested_at, chunk_count})
        -[:HAS_SECTION]->
    (Section {section_id, title, document_id, position})
        -[:HAS_CHUNK]->
    (Chunk {chunk_id, document_id, text_preview, chunk_index})
        -[:MENTIONS]->
    (Entity {name, entity_type})

    Additional edges:
      Document  -[:HAS_CHUNK]->       Chunk    (direct, regardless of section)
      Chunk     -[:NEXT]->            Chunk    (sequential forward)
      Chunk     -[:PREV]->            Chunk    (sequential backward)
      Entity    -[:CO_OCCURS_WITH]->  Entity   (co-occurrence in same chunk)
      Entity    -[:APPEARS_IN]->      Document (direct doc membership)

  What you get that vector search alone cannot provide:
    * Exact entity lookup — deterministic node ID, no corpus scan, no embedding
    * Cross-document links — one entity node shared across all documents
    * Section hierarchy — Document → Section → Chunk navigable structure
    * Sequential navigation — walk reading order via NEXT/PREV
    * Direct document membership — APPEARS_IN skips the chunk hop
    * Co-occurrence graph — entities that appear together in the same chunk

  All existing pipeline behaviour is unchanged — graph_source=None
  (the default) disables the graph layer with zero overhead.

  Backends supported (all from blue-data, no extra code needed):
    MemoryGraphSource  — dev/test, in-process, no infra
    FileGraphSource    — local persistence
    NEO4JSource        — production, Bolt protocol
