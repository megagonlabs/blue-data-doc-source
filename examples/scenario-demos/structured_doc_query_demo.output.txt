FAILURE 2 — Structured questions need structured answers
========================================================================

  Question: "Find all invoices where the total exceeds $30,000"

  Naive approach: search 'invoice total exceeds thirty thousand dollars'.
  Embedding distance cannot evaluate '$35,154 > 30000'. The model can only
  return chunks that are semantically similar to the query — not filter on
  a numeric field extracted from the document content.

  ✗  search('invoice total exceeds thirty thousand dollars', k=5)  —  5 result(s)

  document_type       file                        section                       text preview
  ------------------  --------------------------  ----------------------------  ------------------------------
  contract            beta_contract.txt           (no section)                  CONSULTING AGREEMENT — BETA LTD Thi...
  policy              health_policy.txt           DEDUCTIBLES AND OUT-OF-POCKE  The annual individual deductible is...
  invoice             invoice_aug26.txt           INVOICE                       Invoice Number: INV-2026-0891 Invoi...
  contract            acme_contract.txt           (no section)                  SERVICE AGREEMENT — ACME CORP This ...
  contract            beta_contract.txt           TERMINATION                   Either party may terminate this agr...

  The search returns chunks with the word 'total' — it cannot compare
  '$35,154' against the threshold 30,000. Every RAG library has this problem.

  ✓  FIX: DOCUMENT.FIND with a numeric field filter

    pipeline.find_schemas({
        'document_type': 'invoice',
        'fields.total_due': {'gt': 30000},  # '$35,154' parsed numerically
    })

  -> invoice       total_due='$35,154'
     vendor='Blue Solutions Inc.'
     bill_to='Acme Manufacturing Corp'

  Deterministic. No embedding. No hallucination. Returns exactly the right set.

The Agent Pattern — DOCUMENT.FIND + DOCUMENT.SEARCH
========================================================================

  Real agent queries combine structured filtering with text retrieval.
  DOCUMENT.FIND pins the document. DOCUMENT.SEARCH reads the clause.

  Agent task: 'Summarize the termination terms in Acme Corp's contract.'

  Step 1 — pin the document (no embedding, deterministic):
    contracts = pipeline.find_schemas({'fields.parties': {'contains': 'Acme Corp'}})

Summary — What existing RAG libraries can't do
========================================================================

  Every RAG library (LangChain, LlamaIndex, Haystack) gives you:
    embed query → nearest k chunks → paste into LLM context

  That fails for:
  ✗  'What does ACME CORP's termination clause say?'
       → returns chunks from MULTIPLE contracts; agent cannot tell which is Acme's

  ✗  'Find invoices where total exceeds $30,000'
       → embedding distance cannot evaluate '$35,154 > 30000'

  ✗  'Which contract is governed by California law?'
       → returns chunks from all contracts mentioning California; no definite answer

  blue-data-doc-source fixes this with a two-layer architecture:

  Layer 1 — At ingest time (one API call per document):
    KeywordClassifier → document_type (contract/invoice/policy/...)
    LLMSchemaExtractor → typed fields (parties, governing_law, total_due, ...)

  Layer 2 — At query time (no API calls for filtering):
    DOCUMENT.FIND → deterministic structured filter over extracted fields
    DOCUMENT.SEARCH → text retrieval scoped to the matched documents

  The pattern:
    docs   = pipeline.find_schemas({'fields.parties': {'contains': 'Acme Corp'}})
    chunks = pipeline.search('termination', filters={'document_id': docs[0]['document_id']})
