FAILURE 1 — Semantic search returns the wrong documents
========================================================================

  Question: "What does Acme Corp's termination clause say?"

  Naive approach: search 'termination clause acme corp' across all 5 documents.
  With DummyEmbeddingModel (random vectors), results are unordered — but even
  with real embeddings this query returns chunks from MULTIPLE documents because
  'termination' appears in the policy and both contracts.

  ✗  search('termination clause acme corp', k=5)  —  5 result(s)

FAILURE 2 — Structured questions need structured answers
========================================================================

  Question: "Find all invoices where the total exceeds $30,000"

  Naive approach: search 'invoice total exceeds thirty thousand dollars'.
  Embedding distance cannot evaluate '$35,154 > 30000'. The model can only
  return chunks that are semantically similar to the query — not filter on
  a numeric field extracted from the document content.

  ✗  search('invoice total exceeds thirty thousand dollars', k=5)  —  5 result(s)

  document_type       file                        section                       text preview
  ------------------  --------------------------  ----------------------------  ------------------------------
  contract            beta_contract.txt           (no section)                  CONSULTING AGREEMENT — BETA LTD Thi...
  policy              health_policy.txt           DEDUCTIBLES AND OUT-OF-POCKE  The annual individual deductible is...
  invoice             invoice_aug26.txt           INVOICE                       Invoice Number: INV-2026-0891 Invoi...
  contract            acme_contract.txt           (no section)                  SERVICE AGREEMENT — ACME CORP This ...
  contract            beta_contract.txt           TERMINATION                   Either party may terminate this agr...

  The search returns chunks with the word 'total' — it cannot compare
  '$35,154' against the threshold 30,000. Every RAG library has this problem.

  ✓  FIX (requires OPENAI_API_KEY):

    pipeline.find_records({'document_type': 'invoice', 'fields.total_due': {'gt': 30000}})
    # LLMFieldExtractor extracts total_due='$35,154' at ingest time
    # DOCUMENT.FIND strips '$' and ',' then compares 35154 > 30000 → match
    # Returns: [{document_type: 'invoice', fields: {total_due: '$35,154', ...}}]

The Agent Pattern — DOCUMENT.FIND + DOCUMENT.SEARCH
========================================================================

  Real agent queries combine structured filtering with text retrieval.
  DOCUMENT.FIND pins the document. DOCUMENT.SEARCH reads the clause.

  Agent task: 'What is the termination clause in the contract that expires soonest?'

  Step 1 — find all contracts (deterministic, type filter):
    find_records({'document_type': 'contract'})  ->  2 contract(s)
    document_id=doc_2a86f4fbb254ba8a...
    document_id=doc_ce3d297836e93764...

  [TERMINATION]  Either party may terminate this agreement with sixty days written notice. Acme C...

========================================================================
DOCUMENT.FIND_THEN_SEARCH — Two steps in one call
========================================================================

  The agent pattern above works — but it requires the caller to:
    1. call find_records() to get matching documents
    2. loop over each match and call search() scoped to that doc_id
    3. merge and sort results manually

  DOCUMENT.FIND_THEN_SEARCH encapsulates all three steps:

    source.execute_query({
        'op': 'DOCUMENT.FIND_THEN_SEARCH',
        'find_filter': {'document_type': 'contract'},
        'query': 'termination notice period',
        'k': 4,
        'mode': 'bm25',
    })

  Structured filter pins the candidate set. Text search reads the clause.
  Results from all matched documents are merged and returned sorted by score.

  Result: 2 chunk(s) from contract documents

  document_type       file                        section                       text preview
  ------------------  --------------------------  ----------------------------  ------------------------------
  contract            acme_contract.txt           TERMINATION                   Either party may terminate this agr...
  contract            beta_contract.txt           TERMINATION                   Either party may terminate this agr...

  Chunks span 2 matched contract(s), merged and ranked by score.
  The agent sees one ranked list — no manual merge loop needed.

========================================================================
Summary — What existing RAG libraries can't do
========================================================================

  Every RAG library (LangChain, LlamaIndex, Haystack) gives you:
    embed query → nearest k chunks → paste into LLM context

  That fails for:
  ✗  'What does ACME CORP's termination clause say?'
       → returns chunks from MULTIPLE contracts; agent cannot tell which is Acme's

  ✗  'Find invoices where total exceeds $30,000'
       → embedding distance cannot evaluate '$35,154 > 30000'

  ✗  'Which contract is governed by California law?'
       → returns chunks from all contracts mentioning California; no definite answer

  blue-data-doc-source fixes this with a two-layer architecture:

  Layer 1 — At ingest time (one API call per document):
    KeywordClassifier → document_type (contract/invoice/policy/...)
    LLMFieldExtractor → typed fields (parties, governing_law, total_due, ...)

  Layer 2 — At query time (no API calls for filtering):
    DOCUMENT.FIND             → deterministic structured filter over extracted fields
    DOCUMENT.SEARCH           → text retrieval scoped to matched documents
    DOCUMENT.FIND_THEN_SEARCH → compound: filter + search + merge in one call

  The two-step pattern:
    docs   = pipeline.find_records({'fields.parties': {'contains': 'Acme Corp'}})
    chunks = pipeline.search('termination', filters={'document_id': docs[0]['document_id']})

  Or in one call via DocumentDataSource:
    chunks = source.execute_query({
        'op': 'DOCUMENT.FIND_THEN_SEARCH',
        'find_filter': {'fields.parties': {'contains': 'Acme Corp'}},
        'query': 'termination',
    })

  Or in plain English via NLQueryParser:
    chunks = source.execute_query_nl(
        'find the termination clause in Acme Corp contracts'
    )
